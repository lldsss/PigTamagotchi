# Правила работы с репозиторием

## Общение и основной стек

Общайтесь с пользователем на русском языке: объясняйте решения, сообщайте о ходе работы и описывайте результаты проверок. Пишите простой и читабельный код, избегайте ненужных абстракций.

Основной стек — Python 3.11+ и **aiogram 3** для Telegram-бота. HTTP API и файлы Mini App обслуживает aiohttp в том же процессе. Интерфейс — обычные HTML, CSS и JavaScript без сборки. Прогресс хранится в SQLite.

## Структура проекта

- `src/pig_tamagotchi/__main__.py` — запуск HTTP-сервера, обработчики бота и API.
- `src/pig_tamagotchi/game.py` — правила, награды, уровни и таймеры.
- `src/pig_tamagotchi/storage.py` — сохранение и атомарные действия в SQLite.
- `src/pig_tamagotchi/auth.py` — проверка подписанных данных Telegram.
- `web/` — интерфейс и SVG-свинка.
- `tests/` — тесты игры, авторизации, API и конкурентных действий.

## Запуск и проверки

Создайте виртуальное окружение: `python3 -m venv .venv`, затем активируйте его командой `source .venv/bin/activate`.

- `python -m pip install -e '.[dev]'` — установить приложение и инструменты разработки.
- `cp .env.example .env` — создать локальные настройки.
- `python -m pig_tamagotchi` — запустить приложение; демо доступно на `http://127.0.0.1:8080`.
- `python -m unittest discover -s tests -v` — выполнить тесты.
- `ruff check .` и `ruff format --check .` — проверить Python-код.

Инструкции по подключению бота и HTTPS приведены в `README.md`. Для фронтенда отдельная сборка не требуется.

## Стиль и тестирование

Используйте четыре пробела в Python, два в HTML, CSS и JavaScript. Именуйте функции и переменные Python в `snake_case`, классы — в `PascalCase`. Используйте небольшие функции и понятные имена. Python-код оформляйте через Ruff.

Добавляйте тесты нового поведения и исправлений в `tests/test_*.py` с помощью `unittest`. Покрытие не нормируется. Обязательно проверяйте изменения таймеров, наград и авторизации; время передавайте явно в правила игры. Для интерфейса проверяйте мобильную ширину и состояния загрузки, ошибки и ожидания.

## Коммиты и запросы на слияние

Используйте краткие заголовки коммитов с действием: `Добавить кормление питомца`. Ограничивайте коммит одной связной задачей. В запросе на слияние опишите цель, изменения и выполненные проверки. При наличии добавляйте ссылки на задачи, для интерфейса — снимки экрана.

## Безопасность и конфигурация

Не сохраняйте токены, `.env` и базу игроков в репозитории. Документируйте настройки заглушками в `.env.example`. На рабочем сервере устанавливайте `DEMO_MODE=false`. Определяйте пользователя только по проверенному `initData`; награды и таймеры рассчитывайте на сервере. Сохраняйте атомарность действий и изоляцию игроков.
