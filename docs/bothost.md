# GitHub → BotHost

Проект запускается целиком в одном контейнере: aiogram получает обновления через long polling, aiohttp обслуживает Mini App и API. Локальный туннель не нужен.

## 1. Подключение репозитория

Репозиторий: `https://github.com/lldsss/PigTamagotchi.git`, ветка `main`.

Для приватного репозитория сначала откройте в BotHost раздел **«Git репозитории»** и настройте доступ на чтение. Можно использовать GitHub fine-grained token с доступом только к этому репозиторию и правом **Contents: Read-only**. Токен GitHub вставляйте только в защищённое поле BotHost; это отдельный токен, не токен Telegram-бота.

Документация: https://bothost.ru/docs/git-repository-access

## 2. Создание бота

В BotHost выберите создание из Git и укажите:

- Репозиторий: `https://github.com/lldsss/PigTamagotchi.git`.
- Ветка: `main`.
- Язык: Python / aiogram.
- Токен: токен Telegram-бота от BotFather.
- В дополнительных настройках включите **«Использовать собственный Dockerfile»**. Он уже находится в корне репозитория.
- Если панель требует главный файл, укажите `main.py`. В нашем Dockerfile команда запуска задана явно: `python -m pig_tamagotchi`.
- Включите **«Использовать домен»** и выберите предлагаемый BotHost поддомен.
- Внутренний порт: **8080**.

Скопируйте фактический HTTPS-адрес из панели; зона может быть `bothost.tech` или `bothost.ru`. Не используйте придуманный домен из примера.

Документация: https://bothost.ru/docs/custom-dockerfile и https://bothost.ru/docs/web-apps-domains

## 3. Переменные окружения

Добавьте в настройках бота:

```dotenv
BOT_TOKEN=токен_от_BotFather
WEBAPP_URL=https://фактический-домен-из-панели
DEMO_MODE=false
HOST=0.0.0.0
PORT=8080
DATABASE_PATH=/app/data/pigs.sqlite3
```

Проверьте, что `BOT_TOKEN` задан именно как переменная окружения. Реальный токен не должен попадать в GitHub. `.env` загружать не нужно.

`/app/data` — каталог постоянного хранения BotHost: https://bothost.ru/docs/database-storage

После настройки домена, порта и переменных выполните деплой/пересборку. Если мастер сначала требует создать бота, сохраните его, затем добавьте переменные и повторите деплой. Без токена и правильного `WEBAPP_URL` приложение завершится с сообщением о настройках.

## 4. Проверка

1. Остановите локальный экземпляр бота (`Ctrl+C`), чтобы не было конфликта двух polling-процессов.
2. Откройте `https://ваш-домен/health`: ожидается `{"status":"ok"}`. Это проверка HTTP-сервера, а не соединения с Telegram.
3. Проверьте логи BotHost: бот должен перейти к polling без ошибок.
4. Отправьте `/start` боту в личных сообщениях и нажмите новую кнопку «К моей свинке».
5. Выполните действие, закройте приложение и откройте снова: прогресс сохранится.

В обычном браузере вне Telegram интерфейс откроется, но API потребует авторизацию — играйте через кнопку бота. Webhook для этого проекта настраивать не нужно. Если он ранее был установлен для этого токена, перед polling его нужно удалить.

## Обновления

После изменения кода в GitHub нажимайте обновление из Git/деплой в BotHost. Папку `data/` не добавляйте в репозиторий; делайте резервные копии через средства хостинга. Запускайте один экземпляр бота.
